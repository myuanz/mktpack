# MKP 基础格式

## 文件布局

所有整数采用小端序。MKP 文件依次包含：

| 部分 | 编码 |
|---|---|
| 文件标识 | 8 字节 `MKP\r\n\x1a\n\0` |
| 头部长度 | uint32，表示后续 JSON 的字节数 |
| 头部 | UTF-8 JSON |
| 载荷 | 各列按 `columns` 顺序存放编码流 |

头部保存 `version/rows/time_column/first_time/last_time/symbol/metadata/columns`，空表的首末时间为 null。列描述包含自身的数值尺度、变换、依赖、排列和压缩信息。当前版本为 1

## 列描述

每列保存 `name/type/scale/factor/transform/first/mode/bits/raw_size/size`，需要使用 tick 联合预测时另存 `codec="predictive"`。数值类型为 `timestamp/integer/decimal`，列值使用 int64，实际数值为整数乘以 `10^-scale`。时间为 UTC 毫秒。`symbol` 是文件级常量，查询时可展开为逻辑列。

编码器可以按 schema 声明 `scale_group` 和 `prediction`。同一尺度组先统一十进制尺度，再计算共同 GCD；其他列计算自身 GCD。解码后乘回 `factor`，还原保存的整数。

## 整数变换

| transform | 含义 |
|---|---|
| `constant` | 全列等于 `first`，无载荷 |
| `direct` | 直接保存归一化整数 |
| `changes` | 保存变更点的行距和变化量 |
| `delta` | 以前一行为预测值 |
| `reference` | 以同行指定列为预测值 |
| `level_quantity` | 以前一行同侧同价位数量为预测值 |
| `trade_value` | 以上一累计额加价格、成交量差和合约乘数推算累计额 |
| `ratio_1000` | 保存参照列的千分比量化值 |

变换残差使用 ZigZag 映射为 uint64。`codec="predictive"` 是列级编码标签，用来区分 tick 联合预测与基础列变换，不改变 MKP 版本。预测列的依赖放在列描述中，列投影读取时自动补充依赖列，恢复请求列后丢弃仅用于预测的列。

`ratio_1000` 将 B 相对参照列 V 量化为 `q = round(1000 × B / V)`，范围 0–1000，V 为零时 q 为零，半整数向上取整。列描述保存 `reference` 和是否以 500 为中心，`metadata.lossy_columns` 保存量化步长。比例量化属于列编码，不改变文件版本。

## 排列与压缩

整数流尝试两种排列，并以 Zstd level 9 压缩，保存较短者，相同时选择位平面：

- `mode=0`：按低位到高位保存位平面
- `mode=1`：按低字节到高字节保存八个字节平面

`bits` 为变换后最大值的有效位宽，至少 1。`raw_size` 为解压长度，`size` 为帧字节数。首帧紧接 JSON 头，其余帧偏移由前序 `size` 累加得到。

## 读写与合并

`info()` 只读取头部。`read()` 读取请求列及其预测依赖，逆变换并乘回 `factor`。写入经临时文件完成后替换目标。合并统一每列尺度并按时间稳定排序，保留重复时间的源顺序。

## MKP 载体

完整 MKP 数据流可以直接写入 `.mkp` 文件，也可以作为 BLOB 写入 SQLite。两种载体使用相同的编解码格式。

直接文件的默认路径为 `group/symbol/period.mkp`，eg: `tick/FU2612/2026.mkp`。`period` 粒度由 port 决定，年、月、日分别写为 `YYYY`、`YYYYMM`、`YYYYMMDD`。

SQLite BLOB 载体使用以下表：

```sql
CREATE TABLE blob(id INTEGER PRIMARY KEY, bytes BLOB NOT NULL);
```

每个 BLOB 保存一个完整 MKP 数据流。同一 SQLite 可以保存多个逻辑期间的 MKP 数据流，用于 package 分卷和 CTP tick 归档。

## SQLite 行存储

某些无需压缩的时序数据可保存为 SQLite 实体表。schema 支持 timestamp、integer、decimal、real、string、blob、null 和 any。decimal 可声明固定 scale 或以 `scale_column` 指向逐行尺度。查询采用 `[start,end)`，按时间稳定排列，空结果保持 schema。

非时序数据保存为 SQLite 普通表。读取返回一行字典或多行字典列表；文本中的 JSON 对象、数组恢复为结构值，BLOB 返回 bytes。port 负责业务表结构和写入策略。

## 数据集元数据

系统元数据表使用 `__名称__` 格式，不属于业务数据组。

| 表 | 字段与用途 |
|---|---|
| `__group__` | 数据组的 `id`、`name`、`kind`、`schema`、`storage`、`location`、`table_name`、`time_column`、`symbol_column` |
| `__symbols__` | 品种字典 |
| `__volumes__` | SQLite 载体的唯一 `path` |
| `__timefile__` | MKP 数据流的组、品种、`period`、首末时间、行数和可空 `volume_id` |
| `__sqlite_partitions__` | SQLite 时序实体表的时间分区、载体、行数和首末时间 |

`__timefile__` 以 `(group_id,symbol_id,period)` 为唯一键。`volume_id` 为空时载荷位于直接 MKP 文件；非空时位于 `__volumes__.path` 指向的 SQLite，BLOB id 等于 `__timefile__.id`。

SQLite 路径可以是相对路径或绝对路径。`kind` 为 `timeseries` 或 `ordinary`，`storage` 为 `mkp` 或 `sqlite`。

## 打包

`mkt package` 完整保留非时序业务数据、来源元数据和时序数据，按组、合约、期间和 `[start,end)` 选择时序数据。完整 MKP 数据流直接复制，时间范围切入数据流内部时才解码、裁剪和重新编码。

`--jobs` 控制需要裁剪重编码的载荷并发数，卷写入仍按索引顺序执行。

输出卷默认命名为 `mkt.data.N`，每个路径显式登记到 `__volumes__`。卷可以同时保存 MKP BLOB 和 SQLite 时序实体表。容量按 SQLite 实际页数与页大小计算，当前卷放不下时写入下一卷，单个 MKP 数据流或 SQLite 时序分区不拆卷。SQLite 时序按月筛选写入卷内实体表。目标目录必须为空，失败清理临时产物。package 设置 `PRAGMA application_id=0x4d4b5450`，port 拒绝向 package 写入，package 仍可查询、检查和再次打包。

## CTP 期货卷

CTP tick 的 `__timefile__` 以交易日为 period，松散文件名为 `YYYYMMDD.mkp`。月份结束后，port 为每个合约新建 `YYYYMM.data` SQLite 卷，将当月日载荷写入 BLOB 并更新日级索引。年份结束或合约封存时，将该年月份卷重写合并为 `YYYY.data`，只复制 BLOB，不重新编码 MKP。

`__ctp_futures_series__` 保存镜像及文件名前缀字典。`__ctp_futures_files__(series_id,period,PRIMARY KEY(series_id,period)) WITHOUT ROWID` 的存在表示完整源包已经处理。合约交易日完成状态由日级 `__timefile__` 表达，不另建成员状态表。

## Binance 来源元数据

`__binance_datavision_paths__(id INTEGER PRIMARY KEY,parent_id INTEGER,name TEXT,UNIQUE(parent_id,name))` 按层级保存来源对象键模板。品种与日期分别使用 `{symbol}`、`{period}` 占位符。

`__binance_datavision_templates__` 引用路径末端、组和品种。`__binance_datavision_files__(template_id,period,file_id,error,rows,PRIMARY KEY(template_id,period)) WITHOUT ROWID` 保存期间状态。文件来源通过 file_id 引用 `__timefile__.id`。`__binance_datavision_scans__` 保存发现范围，REST 资金费率使用独立状态表。
