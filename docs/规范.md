# MKP 基础格式

## 文件布局

所有整数采用小端序。文件依次包含：

| 部分 | 编码 |
|---|---|
| 文件标识 | 8 字节 `MKP\r\n\x1a\n\0` |
| 头部长度 | uint32，表示后续 JSON 的字节数 |
| 头部 | UTF-8 JSON |
| 载荷 | 按头部列顺序拼接的独立 Zstd 帧 |

头部保存 `version`（无损文件为 1，含比例量化编码的文件为 2）、`rows`、`time_column`、`first_time`、`last_time`、`symbol`、`metadata` 和 `columns`。空表的首末时间为 null。组索引与单文件都保存 schema；单文件中的数值尺度对应自身数据。

## 列描述

每列保存 `name/type/scale/factor/transform/first/mode/bits/raw_size/size`。当前数值类型为 `timestamp/integer/decimal`，列值使用 int64；实际数值为整数乘以 `10^-scale`。时间为 UTC 毫秒。`symbol` 是文件级常量字符串，在读取时可展开为逻辑列。

编码前将 OHLC 统一到最高小数尺度，并以四列共同 GCD 归一化；其他数值列使用各自 GCD。零列的 factor 为 1。解码后乘回 factor，还原精确整数。

## 整数变换

| transform | 编码值 |
|---|---|
| `direct` | 当前归一化整数 |
| `delta` | 首项为 0，其余为相邻差；首值存入 first |
| `open` | 当前 open 减前一个 close，首项减当前 close |
| `high` | high 减 max(open, close) |
| `low` | min(open, close) 减 low |

时间和 close 使用 delta；完整 OHLC 组使用对应联合变换；其余数值列直接编码。所有变换结果使用 ZigZag 映射为 uint64。

## 排列与压缩

每列尝试两种排列，并以 Zstd level 9 压缩，保存较短者，相同时选择位平面：

- `mode=0`：按低位到高位保存位平面；每平面 `ceil(rows/8)` 字节，第 i 个值占第 i/8 字节的第 i%8 位，末尾补零
- `mode=1`：按低字节到高字节保存八个字节平面，每平面 rows 字节

`bits` 为变换后最大值的有效位宽，至少 1。`raw_size` 为解压长度，`size` 为帧字节数。首帧紧接 JSON 头，其余帧的偏移由前序 size 累加得到。

## 读写与合并

`info()` 只读取头部。`read()` 依次解压、逆变换并乘回 factor。写入经临时文件完成后替换目标。合并统一每列尺度并按时间稳定排序。Python 将整数和尺度恢复为 Arrow decimal，保持精确值。

## 可选比例量化

列 schema 设置 `encoding="ratio_1000"`、`reference="volume"` 时，将数值按参照列的千分比量化。主动买量 B 与总量 V 在共同整数尺度上计算 `q = round(1000 × B / V)`，范围 0–1000，V 为零时 q 为零；半整数向上取整。

该列不使用 GCD，直接 q 与 ZigZag(q−500) 分别尝试位平面和字节平面压缩，选择较短者。描述符记录 `transform="ratio_1000"`、`centered` 和参照列，`factor=1`；文件元信息的 `lossy_columns` 记录比例步长 0.001。

解码后输出值为 V×q/1000，输出 scale 为参照列 scale+3。整数乘积必须能由 int64 表达，scale 不超过 18。恢复值不再次取整到源数量单位，重复合并和编码保持量化结果不变。主动买量误差不超过 V/2000，其余列保持无损。

## 数据集索引

`mkt.sqlite` 使用以下目录表：

| 表 | 字段与用途 |
|---|---|
| `__group__` | `id`、唯一 `name`、`kind`、`schema`、`storage`、`location`、`table_name`、`time_column`、`symbol_column` |
| `__symbols__` | `id` 整数主键、唯一 `name`；每个品种保存一次 |
| `__timefile__` | `id` 整数主键、`group_id`、`symbol_id`、`name`、`first_time`、`last_time`、`rows`、`volume`；`(group_id,symbol_id,name)` 唯一 |

文件只保存短文件名，逻辑路径由 `group_name/symbol/name` 还原。`volume=0` 表示磁盘文件，正整数 N 表示分卷 `mkt.data.N`，载荷 id 为 `__timefile__.id`。

## SQLite 数据组

`kind` 为 `timeseries` 或 `ordinary`；`storage` 为 `mkp` 或 `sqlite`。SQLite 的 `location` 是数据集内相对路径，`table_name` 为空时使用组名。普通表 location 为空表示位于 index；时序表本地保存为独立 SQLite，打包后 location 为空，通过分区目录定位卷。

时序组声明 `time_column`（UTC 毫秒整数，默认 time）和 `symbol_column`（引用主索引 `__symbols__.id`，空字符串表示无品种维度）。SQLite schema 支持 timestamp、integer、decimal、real、string、blob、null 和 any。any 保留 SQLite 同列混合值，以 Arrow dense union 返回；其余类型分别返回对应 Arrow 列。字段可用 column 指定物理列，decimal 可声明固定 scale 或用 scale_column 指向逐行尺度列。symbol 逻辑列由品种字典还原。查询为 `[start,end)`，按时间稳定排列；空结果保持类型，无品种维度的表不附加 symbol 列。

普通表无筛选，返回一行字典或多行字典列表，空表返回空字典；文本内的 JSON 对象、数组恢复为对应结构，BLOB 返回 bytes。表可位于 index 或独立数据库。

port 负责建表、内容和写入策略，通用存储仅依据上述描述读取。资金费率由币安 port 在 funding.sqlite 中定义，所有品种、年份共用一个文件，费率以整数及逐行尺度精确保存。来源覆盖与下载状态通过附加数据库事务一起更新。

## 打包索引与分卷

打包目录包含 mkt.sqlite 和 mkt.data.N。索引经 SQLite backup 复制，保留普通表、下载清单及完整品种字典；外置普通数据库完整携带，不参与容量分卷。时序数据按组、品种及 `[start,end)` 筛选；无品种维度的 SQLite 时序表仅按时间筛选。

MKP 按组、品种、年份归并，载荷放入 `blob(id INTEGER PRIMARY KEY,bytes BLOB)`，由 `__timefile__.volume` 与 id 定位。完整且无需裁剪的年度载荷原样复制，其余合并编码；保留重复时间顺序和已解码的有损值。

SQLite 时序按整月写入卷内 `data_<group_id>` 表，保持原表的列定义与表内约束；各组独立，即使来源数据库使用相同表名也不冲突。`__sqlite_partitions__(group_id,start,end,volume,rows,first_time,last_time,PRIMARY KEY(group_id,start)) WITHOUT ROWID` 记录月份范围、卷号及实际数据概要。读取只打开请求范围对应的卷。MKP 和 SQLite 时序表可共用一卷。

容量按 SQLite 实际页数与页大小计算，年度 MKP、整月 SQLite 数据均不拆分。当前卷放不下时写入下一卷，不填补空余；空卷也放不下时报告所需容量。index 超限仅警告，普通数据库不拆分。目标目录必须为空，失败清理临时产物。包设置 `PRAGMA application_id=0x4d4b5450`，下载器拒绝写入；包仍可查询、检查和再次打包。

## 下载来源索引

`__binance_datavision_paths__(id INTEGER PRIMARY KEY, parent_id INTEGER, name TEXT, UNIQUE(parent_id,name))` 按层级保存路径模板，根节点的 parent_id 为 0。目录和末端文件名各占一个节点，沿父链拼接完整路径；品种与日期分别使用 `{symbol}`、`{period}` 占位符，同一目录及文件名模板跨品种共享。

`__binance_datavision_templates__(id INTEGER PRIMARY KEY, path_id INTEGER, group_id INTEGER, symbol_id INTEGER, UNIQUE(path_id,group_id,symbol_id))` 引用路径末端、组和品种。`__binance_datavision_files__(template_id INTEGER, period INTEGER, file_id INTEGER, error TEXT, rows INTEGER, PRIMARY KEY(template_id,period)) WITHOUT ROWID` 保存各期间状态，template_id 引用 `__binance_datavision_templates__.id`。日期以 YYYYMM 或 YYYYMMDD 整数保存，还原连字符格式后与品种名填入模板，即可恢复完整 key。REST 资金费率单独使用 `__binance_rest_funding__(symbol_id INTEGER, period INTEGER, rows INTEGER, error TEXT, covered_until INTEGER NOT NULL DEFAULT 0, PRIMARY KEY(symbol_id,period)) WITHOUT ROWID`，以品种和日期标识日分区，不写入 Data Vision 路径及模板。covered_until 保存已覆盖的查询终点，延长同日范围时重新获取整日截至该终点的数据；请求范围只参与缓存命名。

文件来源通过 file_id 引用 `__timefile__.id`，资金费率来源通过 rows 记录已写入的行数；对应字段非空且 error 为空表示成功。全量检查分别核对文件存在性和资金费率期间内的行数。
