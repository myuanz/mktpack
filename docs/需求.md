# 金融时序存储与数据适配器

## 当前交付

C++20 提供自描述 MKP 数据文件、SQLite 数据集索引、查询、币安下载、CTP 期货 tick 导入、SQLite 分卷及原生 `mkt`。Python 负责 wheel 分发、Arrow 包装和 raw 接口，主要逻辑由 C++ 执行。

MKP 时序、SQLite 时序和 SQLite 普通表按组描述读写。port 决定数据内容、逻辑期间和归档策略；core、storage 和 package 不按业务来源分支。

## 数据组和物理载体

当下有两种数据: 
1. 时序数据
2. 非时序数据，例如品种信息

时序数据有两种格式: 
1. mkp 时序压缩，例如 kline、tick
2. plain SQLite 行储存，例如资金费率历史

mkp 时序压缩数据有两种载体:
1. 直接的 mkp 文件
2. SQLite BLOB，将 mkp 文件数据流作为 blob 保存到 SQLite，用于打包或者将tick数据放入单文件

## Binance 数据

| 组 | 来源 | 保存字段 |
|---|---|---|
| `kline` | Data Vision `klines/1m` | `time/open/high/low/close/volume/taker_buy_volume` |
| `oi` | Data Vision `metrics` | `time/sum_open_interest/sum_open_interest_value` |
| `funding_rate_settlement` | Data Vision `fundingRate` | `time/funding_rate/interval_hours` |
| `exchangeinfo` | `/fapi/v1/exchangeInfo` | 顶层字段保存为 SQLite 列，嵌套值保存 JSON |

Kline 的 volume 与 taker_buy_volume 使用基础资产数量。下载默认将主动买量按总量的 0.1 个百分点量化，可用 `--no-lossy-taker` 关闭，其他列无损。量化方法由列描述声明，不改变 MKP 版本。

资金费率写入独立 `funding.sqlite`，以品种和结算时间为主键。尚无月归档的尾部通过 REST 补齐。下载器支持增量发现、失败重试、原始 ZIP 缓存和按合约筛选。普通目录与 package 使用相同查询接口。

## 国内期货 tick

`ctp-futures import` 只读取镜像根目录下 `nfs_rq*/tick/future` 的完整 ZIP。源文件名末尾的 `YYYYMMDD` 是交易日，不使用记录内的 `tradingdate`。可选的 `basicinfo/future_instrument` 快照提供标准合约代码、存续日期、最小变动价位和合约乘数。合约目录使用标准代码，不添加交易所前缀。

| tick 组字段 | 来源与含义 |
|---|---|
| `time`、`trading_day`、`symbol` | `trade_timestamp` 的 UTC 毫秒、源文件名日期、标准合约名 |
| `last_price/open_price/highest_price/lowest_price/close_price` | 最新、开、高、低、收 |
| `settlement_price/pre_settlement_price/pre_close_price/upper_limit_price/lower_limit_price` | 当前及前日参考价、涨跌停价 |
| `volume/turnover/open_interest/pre_open_interest` | 累计成交量、累计成交额、持仓量和昨持仓 |
| `bid_price1…5/ask_price1…5/bid_volume1…5/ask_volume1…5` | 五档买卖价格和数量，保留零档位 |

带浮点尾差的价格按合约最小变动价位归整，同合约价格列使用共同尺度和 GCD。成交额直接解析源十进制数。各交易日独立编码，保留重复时间戳和源顺序。

CTP tick 的逻辑期间为交易日：

```text
tick/AP2701/20260102.mkp
```

月份结束后，每个合约新建月份卷：

```text
tick/AP2701/202601.data
```

年份结束或合约封存时，月份卷重写合并为 `2026.data`。日级索引始终保留，归档只改变载荷位置。

只考虑完整源包，不处理跨来源拼接、部分到达或替换。完整源包状态按来源系列和交易日登记，合约交易日完成状态由 `__timefile__` 表达。`--symbols` 扩大范围时依据日级索引补入缺少的合约。

自动跳过文件名在交易日前带 `_F` 后缀的源包。

导入在收盘后由单个进程独占执行，不支持同时导入或导入期间读取。数据可以从完整源包重新生成，导入过程不要求断电持久性。

`ctp-futures import --profile <文件>` 写入导入、编码、索引和归档各阶段的耗时与数据量，用于吞吐分析。

## 查询

数据集和组提供 `describe()`。时序组 `read()` 支持单个或多个 symbol、时间范围和列投影，返回 Arrow table。查询在 SQLite 中筛选组、合约和时间，按 volume 分组批量读取载荷；C++ 只解码请求列及其预测依赖。Python 不承担索引筛选、解码或合并逻辑。

## 验收

自动测试覆盖精确数值往返、列投影依赖、最高小数精度合并、`[start,end)`、重复时间顺序、增量跳过、月年卷迁移、package 再打包和 SQLite 卷路径。真实样本保持只读，生成结果放入 `validation/generated/` 或 `validation/output/`。
