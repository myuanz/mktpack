# 基础格式与币安下载

## 当前交付

C++20 提供自描述 `.mkp` 文件、数据集索引与查询、币安下载、容量分卷打包及原生 `mkt`，所有 CLI 均由 C++ 执行。Python 负责 wheel 分发，并提供 `raw.write/read/info`、`open(root)` 的 Arrow 读取接口。普通目录与打包目录使用相同的读取和检查路径。

首批数据为 USDT UM 永续：一分钟 Kline、五分钟 OI、结算资金费率和最新交易所信息。默认使用精确整数和小数尺度保存，读取为 Arrow decimal；合并逐列采用最高小数精度。时间统一为 UTC 毫秒，查询采用 `[start,end)`，同时间记录保持稳定顺序。

## 三类数据

MKP 时序压缩保存，按 ymd 组织；SQLite 时序在独立数据库中追加，品种维度可选，两者都支持时间筛选、Arrow 读取及分卷。SQLite 普通表放在 index 或独立数据库，无筛选，打包完整保留。SQLite 的字段类型不受 MKP 数值列限制。

port 决定数据内容和写入策略；读取、检查、打包依据组描述，不按业务表名分支。

## 数据映射

| 组 | 来源 | 保存字段 |
|---|---|---|
| `kline` | Data Vision `klines/1m` | `time/open/high/low/close/volume/taker_buy_volume` |
| `oi` | Data Vision `metrics` | `time/sum_open_interest/sum_open_interest_value` |
| `funding_rate_settlement` | Data Vision `fundingRate` | `time/funding_rate/interval_hours` |
| `exchangeinfo` | `/fapi/v1/exchangeInfo` | 顶层字段保存为 SQLite 列，嵌套值保存 JSON，Python 返回 dict |

Kline 的 volume 与 taker_buy_volume 都使用基础资产数量。币安下载默认将主动买量按总量的 0.1 个百分点量化，使用 `--no-lossy-taker` 关闭、`--lossy-taker` 显式启用；其他列无损。选项作用于本次写出的文件，已成功来源仍按增量规则跳过。关闭量化后，已有近似值不会恢复为原始值；需要原始精度时从源数据下载到新目录。OI 保留源单位。资金费率归档的 `calc_time/funding_interval_hours/last_funding_rate` 分别映射到时间、结算周期和费率。

资金费率写入独立的 `funding.sqlite` 的 `funding_rate_settlement` 表，以品种和结算时间为主键，费率使用整数及小数位数精确保存，所有品种、年份共用一个文件。查询仍按品种和时间范围返回 Arrow table，打包时按相同条件筛选记录，整月写入现有 `mkt.data.N` 分卷；当前卷放不下时整体换卷。

资金费率尚无月归档的尾部通过 `/fapi/v1/fundingRate` 补齐。REST 结果不含结算周期，使用相邻实际结算时间差四舍五入到小时；请求包含起点之前的记录以确定首条周期。

官方归档通过公开 S3 桶访问。下载器支持原始 ZIP 缓存；缓存按对象 key 存放，可供独立验收复用。月源包优先；已结束月份和年份按计划合并。增量运行按日期前缀刷新末端目录、跳过已扫描历史范围并重试失败来源，扩大范围会扫描新增区间；全量模式重新发现并核查本地数据。省略 `--symbols` 自动发现全部 USDT 品种。终端按固定工作槽显示阶段，重定向输出时保留阶段摘要和即时错误。

## 本次真实验收

BTCUSDT、DOGEUSDT、ETHUSDT、BNBUSDT，时间范围为 `2024-01-01 <= time < 2026-10-22`，包含 2026-10-21 全天。下载后对照原始 CSV 独立还原数值，检查索引、时间范围与行数。

大小比较使用同一组记录：原始 ZIP/CSV、六列文件、七列文件，以及 taker_buy_volume 独立压缩流。有损文件校验 0.1 个百分点量化结果，其余数值精确对照源数据。持续验证放入 `tests/`；原始数据与生成结果分别放在 `validation/source/` 和 `validation/output/`。
